# ADR-0003：接口选择，不做多网卡合规阻断

状态：Accepted  
日期：2026-09-30

## 背景

旧客户端包含多网卡、多 IP、代理和共享网络检测，并可能以此中止认证。现代系统常同时存在物理 Ethernet、Wi-Fi、Docker/虚拟机 bridge、Tailscale、WireGuard 和其他 TUN 接口。接口数量不代表认证违规。

## 决策

- 平台 crate 枚举操作系统报告的全部接口。
- 无 MAC 的 tunnel 作为正常 `InterfaceInfo` 返回。
- 上层消费者显式选择一个 `InterfaceId` 建立认证会话。
- 每个会话只打开、收发和观察所选接口。
- 其他接口不会导致认证失败，也不会被自动禁用、隐藏或抓取普通业务流量。
- 底层不实现旧版 `MULTIPLE_ADAPTER`、`MULTIPLE_IP` 或代理共享检测策略。

## 后果

- 同一进程可在多个独立 Ethernet 接口上建立不同会话，前提是上层明确请求。
- 自动选择接口只能作为上层策略，必须能向用户展示并允许覆盖。
- 所选接口消失时，仅对应会话失败；不能停止其他接口或全局网络服务。
- 服务端若确有新的多接口产品策略，需要独立需求、安全与隐私评审，不能以“兼容旧客户端”为由进入核心。

## 验收

- 两个同时 up 且有 MAC 的 Ethernet 接口都返回为可用候选。
- Tailscale/WireGuard/TUN 无 MAC 接口可枚举且不会崩溃。
- `AuthMachine` 不接收全局接口数量或其他接口流量。
- 平台 adapter 的 BPF/filter 只安装到调用者选择的接口。
